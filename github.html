Parte 1

Git e GitHub não são a mesma coisa

Pense num jogo de videogame com pontos de salvamento. Você pode salvar antes de uma fase difícil e, se der errado, voltar ao ponto salvo. O Git faz isso com os arquivos de um projeto: guarda cada versão importante e deixa você voltar, comparar e entender o que mudou.

O GitHub é um site onde você coloca esse histórico na internet. Lá ele fica seguro, outras pessoas podem ver e colaborar, e existem ferramentas para revisar, discutir e organizar o trabalho.

programa · roda no seu computador

Git

Ferramenta de controle de versões. Você instala no computador e usa pelo terminal ou por um aplicativo. Funciona sem internet.

site · roda na nuvem

GitHub

Serviço que hospeda repositórios Git e adiciona colaboração: revisão de código, lista de tarefas (issues), páginas de projeto e automações.

Parte 2

Repositório e commit

Um repositório (ou "repo") é a pasta do seu projeto junto com todo o histórico dela. O histórico fica numa pasta escondida chamada .git, que o Git cria e cuida sozinho.

Um commit é uma foto do projeto num momento. Cada commit guarda quem fez, quando, uma mensagem explicando a mudança e um código único chamado hash, como a3f9c1e.

Antes de virar commit, uma alteração passa por três lugares. Experimente abaixo: edite arquivos, prepare com git add e salve com git commit.

Parte 3

    
Branches: caminhos paralelos

    

      
Uma branch (ramo) é uma linha de trabalho separada. Você cria uma branch para testar uma ideia sem mexer na versão principal, chamada main. Se der certo, faz o merge (junção) de volta. Se der errado, é só abandonar a branch.

      
Por dentro, uma branch é só uma etiqueta que aponta para um commit. Nada é copiado. Avance os passos e observe as etiquetas se moverem.

    

  


  

    

      
    

    

      
      

    

    

      

        
        
        
      

      

    

  


  

    

      
E quando dá conflito?

      
Se as duas branches mudaram a mesma linha do mesmo arquivo, o Git não sabe qual versão escolher e pede ajuda. Ele marca o trecho no arquivo assim. Você apaga as marcas, deixa a versão certa (ou combina as duas), salva e faz um novo commit.

      
Conflito não é erro grave. É só o Git perguntando "qual das duas?".

Parte 4

    
Local e remoto: clone, push e pull

    

      
O repositório no seu computador é o local. O que está no GitHub é o remoto, que por costume se chama origin. Eles não se sincronizam sozinhos: você usa três comandos para trocar commits entre os dois.

      
git clone baixa o projeto inteiro pela primeira vez. git push envia seus commits novos. git pull traz os commits que outras pessoas enviaram. Simule abaixo, incluindo o que acontece quando um colega envia algo antes de você.

Parte 5

    
Fork e Pull Request: colaborar sem bagunçar

    

      
Num projeto de outra pessoa, você não pode enviar commits direto. O caminho é fazer um fork, que cria uma cópia do repositório na sua conta do GitHub. Você trabalha na sua cópia e depois abre um Pull Request (PR): um pedido para o dono revisar e juntar suas mudanças ao projeto original.

      
Na sua equipe, quando todos têm acesso ao mesmo repositório, não precisa de fork: basta criar uma branch e abrir o PR a partir dela.

    Parte 6
    
    
    Seu primeiro repositório, passo a passo
    
    
    Abra o terminal (no Windows, o Git Bash que vem com o Git). Os comandos com seu-usuario e meu-projeto precisam dos seus próprios nomes.
    
  
    
  
      
    
    1. 
      
      Instale o Git e crie sua conta
      
      
      Baixe o Git em git-scm.com e crie uma conta gratuita em github.com. Depois confira a instalação:
      
      
      git --version
      
    
      2. 
    
    2. 
      
      Diga ao Git quem é você
      
      
      Faça isso uma vez só. Esse nome e e-mail aparecem em todos os seus commits.
      
      
      git config --global user.name "Seu Nome"
git config --global user.email "voce@exemplo.com"
      
    
      3. 
    
    3. 
      
      Crie o repositório no GitHub
      
      
      No site, clique em New (ou no + no canto superior), dê um nome como meu-projeto e clique em Create repository. Deixe sem README para este exemplo.
      
    
      4. 
    
    4. 
      
      Transforme sua pasta em repositório e faça o primeiro commit
      
      
      cd caminho/da/pasta/meu-projeto
git init
git add .
git commit -m "Primeiro commit"
      
    
      5. 
    
    5. 
      
      Conecte ao GitHub
      
      
      git branch -M main
git remote add origin https://github.com/seu-usuario/meu-projeto.git
      
    
      6. 
    
    6. 
      
      Envie
      
      
      git push -u origin main
      
      
      O GitHub não aceita a senha da conta no terminal. Na primeira vez, entre pela janela do navegador que se abre, ou use um token de acesso pessoal, ou o GitHub CLI (gh auth login). Atualize a página do repositório e seus arquivos estarão lá.
      
    
      7. 
  
    
  
    Prefere não usar o terminal? O GitHub Desktop faz tudo isso com botões, e o VS Code tem uma aba de controle de versões integrada. Os conceitos deste guia valem para qualquer um deles.

    Glossário
    
  
    
  
    
    
    Branch
    Linha de trabalho paralela. Uma etiqueta que aponta para um commit.
    
    
    Clone
    Cópia completa de um repositório remoto no seu computador.
    
    
    Commit
    Uma versão salva do projeto, com autor, data, mensagem e hash.
    
    
    Conflito
    Quando duas mudanças alteram a mesma linha e o Git pede para você escolher.
    
    
    Fork
    Cópia de um repositório de outra pessoa na sua conta do GitHub.
    
    
    .gitignore
    Arquivo que lista o que o Git deve ignorar, como senhas e arquivos temporários.
    
    
    HEAD
    Indica onde você está agora: a branch e o commit atuais.
    
    
    Issue
    Tarefa, bug ou sugestão registrada na aba Issues do repositório.
    
    
    main
    Nome padrão da branch principal. Em projetos antigos pode se chamar master.
    
    
    Merge
    Junção do histórico de uma branch em outra.
    
    
    origin
    Apelido padrão do repositório remoto de onde você clonou.
    
    
    Pull
    Trazer para o local os commits novos do remoto.
    
    
    Pull Request (PR)
    Pedido para revisar e juntar as mudanças de uma branch em outra.
    
    
    Push
    Enviar seus commits locais para o remoto.
    
    
    README
    Arquivo de apresentação do projeto, exibido na página inicial do repositório.
    
    
    Staging
    Área de preparação: o que entra no próximo commit.
